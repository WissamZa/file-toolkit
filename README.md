# File Toolkit

A single-file, menu-driven CLI for organizing photo/PDF folders: create dated
folders, index files into a SQLite database, compile each folder's images and
PDFs into one combined PDF, hard-link the compiled PDFs into a central
directory, and export specific files — all from one interactive menu.

## Features

- **Day folders** — creates `01-MM-YYYY` through `31-MM-YYYY` folders for a
  given month/year in one go.
- **Sort into month folders** — finds every file whose name contains a
  `DD-MM-YYYY` date (separators `-`, `.` or `_` are all accepted) and moves
  it into a `MM-YYYY` month folder, e.g. `01-08-2026.jpg` → `08-2026/`.
  Optionally, each file can be placed inside a day subfolder named after its
  date within the month folder: `08-2026/01-08-2026/01-08-2026.jpg` — files
  sharing the same date end up together. Shows a preview and asks for
  confirmation before moving, can scan subfolders too, and renames
  duplicates (`name (1).ext`) instead of overwriting.
- **Indexing** — scans the working folder's subdirectories and records every
  `.jpg` / `.jpeg` / `.png` / `.pdf` file into a local `files.db` SQLite
  database.
- **Export** — copies out specific indexed files (every `0.jpeg` and every
  date-named `DD-MM-YYYY.jpeg`) into an `export_output/` folder with
  folder-prefixed names.
- **Build PDFs** — compiles each folder's images (and any source PDFs) into
  one borderless PDF, sorted in natural order (`0, 1, 2 … 10`, not
  `0, 1, 10, 2`). PDFs previously generated by this tool are automatically
  skipped so they're never re-ingested as source material.
- **Hard-link PDFs** — hard-links every compiled folder PDF into a central
  `pdf/` directory for easy browsing.
- **One-click pipeline** — runs Index → Build PDFs → Hard-link in sequence.

## Configuration

The toolkit reads a `file_toolkit.conf` (INI-style) at startup: first from
the directory you launch it from, then from the app's own directory. Keys
under `[settings]`:

```ini
[settings]
folder = /home/barg/Documents/scans   ; where the toolkit works
database = files.db                   ; relative values are resolved
export_output = export_output         ;   inside `folder`
pdf_dir = pdf
```

- `folder` — the directory the toolkit operates on (day folders, sorting,
  indexing, PDF building). Use an absolute path to always work on the same
  folder no matter where the app is launched from, or `.` to work in the
  launch directory (the default).
- `database`, `export_output`, `pdf_dir` — locations of the SQLite database
  and the tool's output folders; relative values are anchored inside
  `folder`.

A malformed config file is reported and ignored; missing keys fall back to
their defaults.

## Run from anywhere

Run the installer once — it symlinks the launcher into `~/.local/bin`:

```bash
./install.sh
```

Then start the toolkit from any directory with:

```bash
file-toolkit
```

The launcher finds the project's own files via its symlink location, so it
works no matter where you call it from, and the working folder always comes
from `file_toolkit.conf` as described above.

## Requirements

- Python 3.9+
- [reportlab](https://pypi.org/project/reportlab/)
- [pypdf](https://pypi.org/project/pypdf/)

### Setup with uv (recommended)

This project is configured for [uv](https://docs.astral.sh/uv/). From the
repo root:

```bash
uv sync
```

This creates a `.venv` and installs all dependencies pinned in
`pyproject.toml` / `uv.lock`. Run the tool with:

```bash
uv run file_toolkit.py
```

### Setup with pip (alternative)

```bash
pip install reportlab pypdf
```

## Usage

Run the toolkit from the directory containing your folders of images/PDFs:

```bash
python file_toolkit.py
# or, with uv:
uv run file_toolkit.py
```

You'll see a menu:

```
==================== File Toolkit ====================
 1) Create day folders (01-MM-YYYY .. 31-MM-YYYY)
 2) Index files into database
 3) Export files (0.jpeg and DD-MM-YYYY.jpeg)
 4) Build PDFs from indexed folders
 5) Hard-link compiled PDFs into ./pdf
 6) One click: Index -> Build PDFs -> Hard Link
 7) Sort files into month folders (by date in filename)
 0) Exit
========================================================
```

Pick an option by number and follow the prompts. The banner above the menu
shows which config file and working folder are active.

### Typical workflow

1. **Create folders** for the month you're working with (option 1).
2. **Drop your images/PDFs** into the generated `DD-MM-YYYY` folders.
3. **Index** the files (option 2), or just run the **one-click pipeline**
   (option 6) to index, build PDFs, and hard-link everything in one step.

## Notes

- `files.db` is created in the working folder (see Configuration) and is
  reused across runs — re-indexing only adds new files, it won't duplicate
  entries.
- The `export_output` and `pdf` folders (and the `files.db` file itself)
  are excluded from indexing/build/sorting steps so the tool never
  processes its own output as source material.
- If the app is launched from inside a `MM-YYYY` month folder or a
  `DD-MM-YYYY` day folder, it automatically works from the top-level
  folder above them instead (it prints a notice when it does this), so
  a second month folder is never created inside an existing one.
- The month-folder sorter (option 7) only ever moves *files*, never
  directories — so your `DD-MM-YYYY` day folders are safe. Hidden folders
  (starting with `.`) and the tool's own `export_output` / `pdf` folders
  are skipped, and files that are already inside their matching
  destination (the `MM-YYYY` folder, or the date-named subfolder within it
  when that option is enabled) are left where they are.
